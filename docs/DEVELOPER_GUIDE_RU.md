# MIRRAI: передача проекта разработчику

Начните здесь, затем откройте [архитектуру](ARCHITECTURE_RU.md),
[эксплуатационный справочник](PROJECT_RUNBOOK_RU.md) и
[сценарии AR на разных платформах](AR_CUSTOMER_FLOW.md) и
[план первых магазинов](SALES_PIPELINE.md). Это React/TypeScript-приложение с
файловыми маршрутами Vinext, а не обычный Node-сервер. Публично развернуты только
статические Cloudflare Pages демо; SaaS Worker ещё не опубликован. Целевое
staging использует D1 и KV, production R2 пока не активирован. См.
[статус развертывания](CLOUDFLARE_DEPLOYMENT_RU.md).

## Запуск и проверка

Требуется Node.js >= 22.13 (CI использует Node 22), npm из той же установки Node
и Python для тестов шлюза генерации. Из корня репозитория:

```sh
npm ci
npm run dev -- --port 4177
```

Откройте адрес из вывода сервера (обычно `http://localhost:4177`). На Windows
`localhost` может слушать только IPv6, поэтому `127.0.0.1` не всегда эквивалентен.
Dev-сервер запускается отдельно от проверок:

```sh
npm run verify
python -m unittest discover -s services/reconstruction -p "test_*.py"
```

`verify` последовательно запускает ESLint, TypeScript, аудит размеров GLB,
production-сборку и Node-тесты. Успешный build сам по себе не означает, что
тесты прошли. Не запускайте несколько сборок одновременно: они пишут в `dist`.
Для быстрых чистых unit-тестов можно вызвать `node --test tests/viewer-geometry.test.mjs`.
`tests/rendered-html.test.mjs` требует свежей сборки.

### Окружение и база

- `.openai/hosting.json` содержит логические привязки `DB` и `UPLOADS`, не секреты.
- `vite.config.ts` настраивает локальные D1/R2; `.wrangler` — локальное состояние,
  его нельзя коммитить или включать в deployment-архив.
- На новом checkout локальная база не является копией production. Пустой каталог
  или `no such table` не лечатся заменой production-ID в конфигурации.
- `db/schema.ts` — схема Drizzle, `drizzle/` — история миграций. Новые изменения
  создавайте через `npm run db:generate`, просматривайте SQL перед применением.
  Не редактируйте уже применённые миграции. Не прогоняйте всю историю повторно
  поверх существующей базы без учёта журнала миграций: в ней есть изменения данных.
- Секреты хранятся в локальном игнорируемом окружении и отдельно в runtime Sites.
  `.env.example` и `docs/GOOGLE_LOGIN.md` описывают настройки; значения секретов
  не должны попадать в браузер, URL, логи или Git.
- Публикация Sites и `git push` — разные действия. Успешный GitHub CI не означает,
  что обновилась публичная версия сайта.

## Где менять конкретное поведение

| Задача | Основные файлы |
| --- | --- |
| Лендинг и просмотр одного предмета | `app/page.tsx` |
| Размеры и кадрирование, без React/DOM | `lib/viewer-geometry.mjs` |
| Подсказка Safari/Chrome, распознавание встроенного браузера | `lib/ar-platform.mjs` |
| Каталог HUGGE, карточка, цвета, фотогалерея | `app/demo-store/store.tsx` |
| Публичный каталог и доступность моделей | `app/api/storefront/catalog/route.ts` |
| Скрипт магазина, поиск SKU, iframe, события | `public/mirrai-widget-2.4.0.js` |
| Проверка домена, подписки, товара | `app/api/widget/bootstrap/route.ts`, `app/api/widget/config/route.ts`, `app/api/widget/cors.ts` |
| Учёт событий и статистика | `app/api/widget/events/route.ts`, `app/api/admin/analytics/route.ts` |
| Магазины и права участников | `db/authorization.ts`, `db/authorization-policy.mjs`, `app/api/admin/clients/route.ts` |
| Регистрация, пароль, Google | `app/api/auth/` |
| Срок подписки и её ограничения | `db/subscription.mjs`, `app/api/admin/subscription/route.ts` |
| Товары, загрузка файлов, публикация | `app/api/admin/catalog/route.ts`, `app/api/admin/assets/route.ts` |
| Очередь 3D-генерации и GPU-шлюз | `app/api/internal/generation/tick/route.ts`, `services/reconstruction/` |
| Таблицы и файловое хранилище | `db/schema.ts`, `db/index.ts`, `db/storage.ts` |

Путь покупателя: карточка магазина → SDK → серверная проверка доступа →
iframe просмотрщика → загрузка GLB → проверка размеров → запуск доступного AR.
События iframe принимает SDK и передаёт серверу статистики. У события запуска
и подтверждённого размещения разные значения: нативные AR-просмотрщики не всегда
возвращают подтверждение размещения, поэтому нельзя считать их одной метрикой.

## Правила, которые нельзя случайно сломать

1. **Магазины изолированы на сервере.** Не доверяйте `shopId`, роли или статусу
   подписки из формы/URL. Новые административные API должны использовать
   существующую авторизацию и проверку membership, как соседние маршруты.
2. **Браузерный SDK не содержит секретный API-ключ.** Доступ проверяется сервером.
   Параметры viewer URL описывают внешний вид и не заменяют авторизацию.
   Уже публично выданный GLB нельзя превратить в DRM-защищённый файл блокировкой кнопки.
3. **Публикуется только проверенная модель.** Генерация заканчивается в `review`,
   не в `published`. Наличие файла не означает доступность AR покупателю.
4. **Сантиметры каталога ≠ метры GLB.** `width → x`, `height → y`, `depth → z`.
   Проверка допускает 5 мм или 0.5% по каждой оси для округления. Это проверка
   цифровых размеров, не гарантия миллиметровой точности трекинга камеры.
5. **Зум превью не меняет размер мебели.** Меняйте камеру, не физический масштаб.
   В AR сохраняйте `ar-scale="fixed"`. Scene Viewer заново скачивает исходный
   GLB и не применяет runtime scale: ему нужны заранее записанные размеры.
6. **Запуск AR требует жест пользователя.** Не добавляйте сетевой `await` перед
   `activateAR()`. Доступ проверяется заранее; просроченная проверка блокирует запуск.
7. **Асинхронные эффекты должны отменяться.** После ожидания кадров/загрузки
   проверяйте, не переключил ли пользователь товар; удаляйте listeners и observers.
8. **Опубликованные версии SDK неизменяемы.** Не правьте старый версионированный
   файл под тем же URL. Для изменения поведения выпускайте новую версию, обновляйте
   alias `mirrai-widget.js`, мастер установки, документацию и тесты совместимости.
9. **HUGGE — специальное демо.** Исключение по сроку в `db/subscription.mjs`
   относится только к `hugge-md`; ручная приостановка действует. Уберите исключение
   при переводе этого магазина на платный тариф, не распространяйте его на клиентов.

## Стиль кода

- Компоненты называйте по назначению (`DemoStore`), обработчики — по действию
  (`selectVariant`), переменные с единицами — `dimensionsCm`, а не абстрактное `data`.
- React использует функции и hooks. Не вводите классы ради классов: чистые вычисления
  держите в `lib/`, работу с БД — на сервере, UI — в компонентах.
- Комментарий должен объяснять **почему**: ограничение AR-платформы, единицы,
  границу доверия, отмену запроса. Не комментируйте очевидные присваивания.
- Существующие CSS-классы — часть связки JSX/CSS/SDK. Сохраняйте смысловые имена
  вроде `ar-launcher`, `ar-phone-handoff`, `photo-lightbox`; переименовывайте вместе
  со всеми селекторами, а не только в JSX.
- Для изменяемых TSX-файлов используйте читаемое форматирование. Пример:
  `npx prettier@3.6.2 --write app/page.tsx --arrow-parens avoid --print-width 100`.
- Для расчётов/прав доступа пишите поведенческие тесты с входами и результатами.
  Проверка текста исходника регуляркой — только дополнительный контракт,
  она не доказывает, что кнопка работает в браузере.

## Перед выпуском

- `npm run verify` и Python-тесты зелёные; diff проверен, секретов нет.
- В каталоге открыть кресло и длинный стол; сменить доступный цвет; открыть и
  пролистать фото; вернуться назад; проверить узкий экран и отсутствие обрезания.
- Превью: вращение и зум; масштаб AR остаётся 1:1; быстрое переключение товара
  не показывает статус предыдущей модели.
- Проверить отказ доступа: чужой магазин, отключённая подписка, неопубликованный SKU.
- На реальных iPhone/Safari и Android/Chrome: камера, поиск пола, размер, возврат
  в магазин. Во встроенном браузере — понятный fallback, а не скачивание архива.
- Зафиксировать commit, дождаться CI и успешного deployment. Сохранять различие
  между проверенным API, визуальной проверкой и проверкой на реальном телефоне.

## Границы готовности

Автотесты не оценивают сходство генерации с фотографией и реалистичность ткани.
Нельзя обещать AR-камеру в любом браузере: поддержка зависит от устройства,
системы и контейнера приложения. Подключение платёжного провайдера, реальные
Google OAuth credentials и доступность GPU требуют отдельной эксплуатационной
настройки; наличие экранов кабинета не доказывает, что эти внешние сервисы подключены.

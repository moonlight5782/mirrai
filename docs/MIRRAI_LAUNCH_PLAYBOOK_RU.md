# MIRRAI — единый план пилота и запуска

**Дата сверки:** 17 октября 2026 г.  
**Статус:** подготовлен код SaaS и staging-конфигурация; публично доступны только статические демо. SaaS Worker ещё не прошёл подтверждённый staging-деплой.

Это главная рабочая страница проекта. Notion-страница [«MIRRAI: инструкция по сборке и запуску»](https://app.notion.com/p/3fc8b08190b181af8f02feddbd4b9576) содержит пошаговые действия для владельца аккаунтов. Этот документ и Notion должны описывать один и тот же статус; при расхождении сверяемся с кодом, GitHub Actions и фактическим URL.

## Что уже можно показать

- [Нейтральный каталог-демо](https://mirrai-furniture-demo.pages.dev/) — отдельный статический сайт с каталогом и подготовленными 3D-моделями.
- [Персональное демо HUGGE](https://mirrai-hugge-demo.pages.dev/) — показывать только HUGGE.
- В репозитории есть SaaS-код: вход через Google или email/пароль в зависимости от режима, роли и разделение магазинов, кабинет, товары, импорт каталога, загрузки, очередь моделей, админка, виджет и события аналитики.
- В коде есть staging-деплой на Cloudflare Workers Free + D1 + KV и отдельный workflow GitHub Actions.
- Статические демо независимы от SaaS Worker; их доступность не подтверждает готовность кабинета или сервиса для магазина.
- Последняя локальная проверка: `npm run verify` — lint, typecheck, production build, аудит размеров и 87 Node-тестов; отдельно прошли 2 Python-теста шлюза.

## Сверенное состояние и ограничения

| Область | Фактическое состояние | Что будет считаться готовым |
|---|---|---|
| Демо | Публичные Pages-каталоги; они не синхронизированы с живыми магазинами | Проверены ссылки, карточки, цвета, просмотр 3D и мобильный AR |
| SaaS-приложение | Реализовано в исходниках, но Worker не подтверждён как опубликованный | Staging URL открывается, пользовательский сценарий пройден на нём |
| Инфраструктура | По прежней настройке созданы отдельные D1/KV и GitHub Environment `mirrai-staging`; наличие секретов сейчас нужно подтвердить в GitHub | Workflow проходит verify, миграции, deploy и smoke tests |
| Аккаунты | Для staging выбран Google-only; OAuth callback готов, но Google credentials ещё не внесены | Проверены новый и повторный вход через Google, роли и изоляция магазинов |
| Каталог и модели | Импорт CSV/sitemap и загрузки есть в коде; реальный SaaS-процесс не проверен | Один товар проходит импорт → модель → QA → публикация → виджет |
| Генерация | Интеграция с Hugging Face Space или собственным шлюзом предусмотрена, но GPU-сервис и очередь не подтверждены end-to-end | Задание реально проходит до результата; геометрия/текстура проверены, есть retry и понятный статус |
| Виджет и аналитика | SDK/API/events есть в коде; живой магазин не подключён | На тестовом сайте корректно определяется SKU, открывается viewer/AR, события видны в кабинете |
| Оплата | Checkout и webhooks не реализованы; статус подписки в коде не является подтверждением оплаты | Провайдер, работающий с продавцом в Молдове, проходит оплату, webhook и отмену |
| Production | Не развёрнут; R2 и платные ресурсы не включены | Выбраны хранилище/бэкапы, мониторинг, домен и проверена процедура восстановления |

## Единый путь магазина

```text
Публичная страница MIRRAI
  → нейтральное демо
  → вход/создание аккаунта через Google
  → заявка/создание магазина и проверка домена
  → каталог (CSV, sitemap или вручную)
  → импорт 3D-файлов ИЛИ фотографий + размеры
  → предварительная стоимость и согласование объёма
  → обработка модели (автоматически только при подключённом GPU-сервисе)
  → ручная проверка качества и масштаба оператором
  → публикация модели
  → установка SDK без секретного ключа в HTML магазина
  → тест кнопки, 3D, AR и событий аналитики
  → пилот и ручное выставление счёта
  → после юридической и платёжной готовности: checkout и автоматическая подписка
```

До staging не предлагать самостоятельную регистрацию магазина как работающий сервис. В режиме Google тестовый consent screen пускает только добавленные тестовые аккаунты; это ещё не открытая регистрация для любого пользователя. Сейчас допустимо показывать демо и договариваться о дизайн-партнёрстве/ограниченном пилоте; не обещать автоматическую генерацию каталога, любую тему CMS, гарантированный фотореализм или готовую оплату.

## Порядок работ — без перескакивания этапов

### A. Подготовить и развернуть бесплатный staging

1. Проверить в GitHub Environment `mirrai-staging` переменные Cloudflare, D1, KV, origin, режим `google` и email оператора.
2. Добавить отдельный минимально привилегированный Cloudflare Workers API token в secret `CLOUDFLARE_WORKERS_API_TOKEN`; не менять Pages token.
3. Создать Google OAuth Web client; добавить `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` в secrets staging. Redirect URI: `<MIRRAI_APP_ORIGIN>/api/auth/google/callback`. Добавить тестовые аккаунты в Google consent screen.
4. При наличии GPU endpoint добавить `HUGGINGFACE_SPACE_URL` и, если Space закрытый, `HUGGINGFACE_TOKEN`; либо `RECONSTRUCTION_API_URL` и `RECONSTRUCTION_API_TOKEN` для собственного шлюза. URL — variables, токены — secrets. Эти настройки не создают сам GPU-сервис.
5. Запустить GitHub Actions → **Deploy MIRRAI SaaS** на `main`. Workflow только staging; R2/production не включать.
6. Проверить новый и возвращающийся Google-аккаунт, отмену OAuth, отказ неприглашённому тестовому аккаунту, создание магазина, права доступа, D1 и KV-загрузку.

### B. Пройти один полный пилотный товар

1. Создать тестовый магазин и импортировать 1–3 SKU с фотографией, цветом, ссылкой и точными размерами.
2. Загрузить имеющуюся проверенную модель или поставить фото в очередь; если нет GPU endpoint — явно показать заблокированный/ручной этап, не выдавать фиктивный результат.
3. Проверить модель на силуэт, материалы, цвет, геометрию, размеры и положение на полу; публиковать только после QA.
4. Подключить виджет к тестовой странице магазина. Проверить разрешённый домен, SKU, модель, fallback и отсутствие влияния на корзину/покупку.
5. Пройти на реальных устройствах: iPhone Safari/Quick Look и Android Chrome/Scene Viewer. Встроенные браузеры проверять отдельно; не заявлять «работает в любом браузере» без матрицы тестов.
6. Проверить события `widget_open`, `model_ready`, `ar_open`, `object_placed` и изоляцию аналитики между магазинами.

### C. Коммерческий запуск

1. До оплаты — дизайн-партнёрский пилот с письменным объёмом, правами на фото/модели и ручным контролем результата.
2. Зафиксировать раздельную цену: подготовка моделей (по SKU/сложности) и ежемесячное обслуживание виджета.
3. До выставления коммерческого счёта оформить подходящую деятельность в Молдове и выбрать доступный юридически платёжный канал. Пока компании/ИП нет, автоматический checkout не подключать и не представлять пробный период как оплаченную подписку.
4. Только после одного-двух подтверждённых пилотов: выбрать платёжного провайдера, реализовать checkout/webhooks, протестировать продление/отмену/возврат, затем открыть самостоятельное подключение.

## Ближайший технический шаг и текущий блокер

Ближайшее безопасное изменение в репозитории — деплой должен передавать в Worker настройки GPU-сервиса, если владелец добавил их в GitHub Environment. Это изменение внесено в `scripts/deploy-saas.mjs` и `.github/workflows/deploy-saas.yml`; далее его нужно проверить lint/typecheck/tests.

С самого компьютера здесь нет `gh` CLI, поэтому проверить наличие secrets в GitHub Environment и запустить Actions из рабочей копии нельзя. Значения секретов не запрашивать в чате. Владелец добавляет `CLOUDFLARE_WORKERS_API_TOKEN`, `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` через GitHub Settings; после этого запуск и проверка возможны через GitHub Actions UI. `RESEND_API_KEY` и `MAIL_FROM` в staging Google-only не нужны.

## Условия считать запуск завершённым

- Staging Worker опубликован, домен открывается по HTTPS, D1 миграции применены.
- Вход Google работает для оператора и владельца; восстановление доступа выполняется через Google.
- Проверена изоляция минимум двух магазинов и ограничение домена виджета.
- Один товар прошёл импорт, модель/QA/публикацию, установку виджета, мобильный AR и аналитику.
- Результаты проверены по опубликованному staging, а не только по локальным тестам или статическому демо.
- Платёжный запуск выполняется отдельным этапом после решения юридических вопросов и реализации webhook-потока.
